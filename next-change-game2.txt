# FASE — TESTE END-TO-END REAL DO ADMIN → GAME → rAthena

Agora quero uma bateria de **testes funcionais reais**, usando as modificações feitas pelo Admin em `localhost:3000` e verificando o resultado efetivamente dentro de `/play`.

O objetivo NÃO é apenas verificar que o formulário salva no banco. Cada alteração deve ser seguida até o comportamento real no jogo.

## REGRA PRINCIPAL

Para cada recurso:

`Admin :3000 → API → banco/arquivo → runtime/game → comportamento observado`

Uma alteração só deve ser considerada **PASS** se o comportamento correspondente for comprovado no `/play` ou no runtime apropriado.

Não considere:

* HTTP 200 sozinho;
* registro salvo no banco;
* JSON correto;
* arquivo correto;
* typecheck;
* teste unitário;

como prova de funcionamento do recurso.

Esses são apenas passos intermediários.

---

# 1. PRIMEIRO: GARANTIR QUE O /PLAY USA AS ALTERAÇÕES DO :3000

Antes da bateria completa, descubra e documente:

1. Como `localhost:3000` se comunica com o `/play`.
2. Qual API o `/play` utiliza.
3. Qual banco/configuração o `/play` utiliza.
4. Qual servidor/runtime fornece os dados para o `/play`.
5. Se existe cache entre Admin → API → banco → `/play`.
6. Como uma alteração feita no Admin chega ao jogo.
7. Qual procedimento de reload/restart é necessário, se houver.
8. Faça uma alteração de teste pequena e inequívoca pelo Admin.
9. Confirme dentro do `/play` que a alteração chegou.

Use uma alteração facilmente identificável, por exemplo um nome/descrição temporária.

**Não assuma que o :3000 e o /play estão conectados só porque ambos funcionam. Prove o caminho dos dados.**

# 12. CRITÉRIO DE PASS/FAIL

Para cada caso registrar:

| Recurso | Operação | Admin     | Banco/arquivo | Runtime   | /play     | Resultado |
| ------- | -------- | --------- | ------------- | --------- | --------- | --------- |
| ...     | ...      | PASS/FAIL | PASS/FAIL     | PASS/FAIL | PASS/FAIL | PASS/FAIL |

Um caso só é **PASS** quando todas as etapas necessárias forem comprovadas.

Se o Admin salva mas o jogo não muda:

**FAIL de integração.**

Se o banco muda mas o arquivo/runtime não:

**FAIL de sincronização.**

Se o runtime recebe mas o `/play` não mostra:

**FAIL de integração do game client/runtime.**

Se a funcionalidade não existe no sistema atual:

**N/A — não tentar inventar implementação apenas para preencher a matriz.**
