
# Objetivo

Quero publicar **apenas o cliente** do meu MMORPG no Vercel para que um amigo consiga acessar pela internet e jogar comigo, enquanto **todo o backend continua rodando no meu computador**.

Não quero alterar a arquitetura do projeto além do necessário para isso funcionar.

---

# Arquitetura atual

O projeto é um monorepo PNPM.

Serviços atualmente:

* rAthena (WSL2)

  * Login Server: 6901
  * Char Server: 6122
  * Map Server: 5122

* API

  * apps/api
  * localhost:4000

* Gateway Socket.IO

  * apps/gateway
  * localhost:4100

* Cliente

  * apps/game
  * Vite
  * localhost:3001

Hoje tudo funciona localmente.

Quero apenas permitir que um amigo acesse pela internet.

---

Quero que o fluxo fique assim:

Amigo

# Requisitos

## 1. Remover dependência de localhost

Procure todos os lugares onde exista algo como:

* localhost:4000
* localhost:4100
* http://localhost
* ws://localhost

Substitua por variáveis de ambiente.

Não quero nenhum fallback para localhost em produção.

Se a variável não existir, o projeto deve falhar com erro explícito.

---

## 2. Centralizar URLs

Se atualmente existir:

VITE_API_URL

e

VITE_GATEWAY_URL

avalie se é possível centralizar em:

VITE_SERVER_URL

de forma que:

fetch()

e

Socket.IO

utilizem a mesma origem.

Caso isso seja inviável pela arquitetura atual, explique por que e mantenha duas variáveis.

---

## 3. Preparar Vercel

Crie tudo que for necessário para hospedar apenas apps/game.

Incluindo:

* vercel.json
* rewrites
* SPA fallback
* configuração correta para Vite
* monorepo PNPM
* Include files outside root
* qualquer ajuste necessário

---

## 4. Garantir HTTPS

O cliente ficará hospedado em HTTPS.

Verifique todo o código para garantir que:

* nenhum fetch utilize http://
* nenhum Socket.IO utilize ws://
* tudo utilize automaticamente HTTPS/WSS.

---

## 5. Revisar CORS

Revise API e Gateway.

Confirme se realmente estão preparados para aceitar chamadas vindas do domínio do Vercel.

Se encontrar qualquer problema, corrija.

---

## 6. Revisar Build

Quero que o build do cliente seja totalmente compatível com Vercel.

Faça uma revisão completa de:

* import.meta.env
* Vite
* paths
* assets
* public
* base path
* lazy loading
* router

---

## 7. Revisar Router

Como usamos createBrowserRouter, confirme que:

/login

/char-select

/play

e qualquer outra rota continuem funcionando após atualizar a página.

Se necessário, configure rewrites.

---

## 8. Revisar Socket.IO

Verifique:

* reconexão
* heartbeat
* timeout
* transporte websocket
* fallback polling

Quero garantir que funcione normalmente através de HTTPS.

---

* imports quebrados
* dependências incompatíveis
* problemas de build
* mixed content
* CORS

* assets

* código dependente de desenvolvimento

---

Antes de considerar concluído:

* corrija todos os erros encontrados

Não quero deixar nenhum erro pendente.
